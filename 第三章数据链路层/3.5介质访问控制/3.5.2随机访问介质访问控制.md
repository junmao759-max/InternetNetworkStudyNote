###### 一、ALOHA 协议（纯 ALOHA + 时隙 ALOHA）

###### 1. 纯 ALOHA

1. 规则：站点有数据**随时直接发送**，不用提前侦听信道。
2. 冲突判断：超时没收到确认 = 判定冲突，等待**随机时长**重传，反复直到成功。
3. 冲突区间：**2T₀**（T₀为一帧发送时长），极易冲突，信道吞吐量极低。
4. 缺点：无任何限制，冲突概率高，效率差。

###### 2. 时隙 ALOHA（优化版）

1. 全网时钟同步，时间切分为等长时隙 Slot，**仅时隙起点允许发帧**。
2. 冲突窗口缩小为 T₀，冲突概率减半，吞吐量相比纯 ALOHA 提升一倍。
3. 冲突后重传逻辑和纯 ALOHA 一致：随机等待重传。

###### 核心对比

纯 ALOHA：任意时刻发；冲突窗口 2T₀

时隙 ALOHA：只能时隙起始发；冲突窗口 T₀

###### 二、CSMA 载波监听多路访问（ALOHA 改良，发送前先侦听信道）

核心改进：发数据前先监听信道，空闲才发，大幅降低冲突；分为 3 类。

表格

|协议|信道空闲|信道忙|
|---|---|---|
|1 - 坚持 CSMA|立刻发送|持续监听，信道一空闲立即发（发送概率 = 1）|
|非坚持 CSMA|立刻发送|停止监听，等随机时间再重新监听|
|p - 坚持 CSMA（适配时分时隙）|以概率 p 发帧；概率 1-p 推迟到下一时隙再监听|持续等到下一个时隙再监听信道|

1. **1 - 坚持**
    
    优点：空闲信道立刻占用，信道利用率高；缺点：多个节点同时侦听到空闲，会同时发送，依旧容易冲突。
2. **非坚持**
    
    优点：忙时放弃监听，大幅降低多节点同时发送的冲突；缺点：随机等待带来额外时延，信道空闲也会空等。
3. **p - 坚持**
    
    折中方案，适配时隙网络。缓解 1 - 坚持的高冲突、非坚持的高时延；空闲时隙带概率发送，平衡冲突与时延。

###### 三、CSMA/CD 载波监听多路访问 / 冲突检测（以太网有线总线网专用）

###### 1. 适用范围

总线以太网、半双工网络；**全双工不需要 CSMA/CD**（收发两条独立信道，无冲突）。

核心口诀：**先听后发、边发边听、冲突停发、随机重传**。

###### 2. 完整工作流程

1. 准备：分组封装成帧放入缓存。
2. 侦听：信道忙持续等待；信道空闲且维持 9.6μs 最小间隔，开始发送。
3. 边发边检测：发送全程监控信道电压；检测到冲突立刻终止发帧。
4. 冲突处理：执行**截断二进制指数退避算法**，等待随机时间重传；重传 16 次失败则放弃，向上层报错。

###### 3. 争用期（冲突窗口）

单程传播时延 =τ；争用期 =**2τ**（往返时延）。

节点最多经过 2τ 就能确认本次发送是否冲突；只有完整熬过 2τ 无冲突，代表发送安全。

###### 4. 最短帧长必考公式

最短帧长 = 往返传播时延 × 数据传输速率 = \(2τ×R\)

以太网经典参数：争用期 51.2μs，速率 10Mb/s → 最短帧 64 字节。

- 小于 64B 的帧：必然是冲突中途终止的无效帧，接收方直接丢弃。
- 不足 64B 需要 MAC 层填充比特补齐。

###### 5. 截断二进制指数退避算法

1. 基础退避时间：\(2τ\)（争用期）。
2. 重传第 k 次，随机数\(r∈[0, 2^k-1]\)，等待时延 =\(r×2τ\)；限制\(k=min(重传次数,10)\)，重传≥10 次后 k 固定为 10。
3. 重传上限：连续重传 16 次失败，判定网络拥塞，丢弃帧并报错。
4. 特点：重传次数越多，可选等待区间越大，动态降低再次冲突概率。

###### 补充细节

以太网帧最小间隔 9.6μs，保证接收方缓存处理完毕。

###### 四、CSMA/CA 载波监听多路访问 / 冲突避免（802.11 无线局域网 WiFi）

###### 1. 为什么无线不用 CSMA/CD

1. 无线信号强弱波动大，硬件很难低成本实现边发边测冲突；
2. **隐蔽站问题**：A、B 互相听不到，但都能和 AP 通信，双方同时发包给 AP 产生冲突，发送端无法察觉冲突。
    
    CSMA/CD 是冲突后检测；CSMA/CA 是**尽量提前规避冲突**，无法做到完全无冲突。

###### 2. 核心机制

1. 发送全程依靠**停止等待 ARQ**：发一帧必须收到 ACK 确认才能发下一帧；无 ACK 必须重传。
2. 帧间间隔 IFS（Inter_Frame Space）：信道空闲后，必须等待对应 IFS，才可发送，划分优先级。
    
    - SIFS（Short Inter_Frame Space）（短 IFS，优先级最高）：ACK、CTS、分片帧、探测回复使用；间隔最短，优先占用信道。
    - PIFS（PCF Inter_Frame Space）（点协调 IFS）：PCF 集中轮询模式使用。
    - DIFS（DCF Inter_Frame Space）（分布式 IFS，最长）：DCF 默认，普通数据帧、管理帧使用。
    
3. 虚拟载波监听 NAV：RTS/CTS 告知全网信道占用时长，其他站点在 NAV 倒计时内静默，不用物理侦听。

###### 3. DCF 默认发送完整步骤（绝大多数 WiFi 使用）

1. 信道空闲，等待 DIFS；
2. 进入竞争窗口，执行随机退避倒计时；倒计时归零才能发帧；
3. 发送完整帧，等待 SIFS 后对方回 ACK；收不到 ACK 则重传。

###### 4. 隐蔽站解决方案：RTS/CTS 预约机制

流程：

1. 源站：信道空闲 + DIFS → 发送 RTS（携带本次通信总时长）；
2. AP：收到 RTS，等待 SIFS → 回复 CTS（携带占用时长）；
3. 全网所有站点收到 CTS，设置 NAV，NAV 倒计时内禁止发送；
4. 源站收到 CTS，SIFS 后发数据；AP 收完数据 SIFS 回 ACK。

特点：RTS/CTS 帧很短，就算碰撞开销很小；大数据帧推荐开启，小数据帧可关闭节省开销。

NAV 含义：全网根据 CTS 记录信道被占用的总时长，实现虚拟监听。

###### 5. CSMA/CA 退避算法

第 i 次重传，随机数范围 \(0~(2^{2+k}-1)\)；上限 255，不再扩大区间（和 CSMA/CD 上限 1023 区分）。

需要触发退避的场景：初次发帧信道忙、重传、发完一帧要继续发下一帧。

###### 五、CSMA/CD vs CSMA/CA 核心区别汇总

表格

|维度|CSMA/CD|CSMA/CA|
|---|---|---|
|使用场景|有线以太网（总线、半双工）|无线局域网 802.11 WiFi|
|冲突逻辑|边发边检测，冲突立刻停发|无法检测冲突，依靠预约、随机时延规避冲突|
|重传依据|冲突检测到就重传|依靠 ACK 确认，无 ACK 则重传|
|检测方式|电缆电压波动|无线能量 / 载波检测 + 虚拟 NAV|
|发送行为|冲突当下中断帧|一旦开始发送，必须把整帧发完|
|典型优化|最短帧长、二进制退避|IFS 分级、RTS/CTS、NAV 虚拟监听|

###### 六、隐蔽站 总结

1. 定义：两个终端彼此不在对方无线覆盖区（互相听不见），但都能连通 AP；两者同时发包给 AP 产生冲突，发送方感知不到。
2. 解决：RTS/CTS+NAV，依靠 CTS 让全部站点知晓信道占用时间，避免同时发送。

###### 七、随机访问整体优缺点

优点：实现简单，无需集中管控，节点灵活接入；

缺点：网络负载高时冲突暴涨，吞吐量暴跌，稳定性差。
