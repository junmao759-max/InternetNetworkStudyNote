###### 1、应用场景

① 用户主机 ↔ ISP（拨号入网）；② 两台网络设备直连专线。

> HDLC 新大纲已删除，不再记忆。

###### 2、PPP 三大组成部分

1. **LCP 链路控制协议**：建立、配置、测试**数据链路连接**，协商链路参数（MTU、认证等）。
2. **NCP 网络控制协议**：为不同网络层协议配置逻辑连接；IP 使用的 NCP 叫 **IPCP**，用来分配 IP 地址。
3. 将 IP 数据报封装到串行链路的方法，受 MTU 限制。

###### 3、PPP 帧格式（重点）

表格

|字段|字节数|说明|
|---|---|---|
|F 标志字段|1|`0x7E`，帧开始 / 结束定界符。信息段出现 0x7E 需要转义。|
|A 地址字段|1|固定`0xFF`，无实际意义|
|C 控制字段|1|固定`0x03`，无实际意义|
|协议字段|2|区分信息部分载荷类型|
|信息部分|0~1500B|载荷，可以为 0 字节！|
|FCS 校验|2|CRC 冗余校验|
|F 标志字段|1|`0x7E`结束标记|


> 协议字段取值：

- `0xC021`：信息是 **LCP 报文**（链路控制）
- `0x8021`：信息是 **NCP (IPCP) 报文**（网络层协商 IP）
- `0x0021`：信息是 **IP 数据报**（用户业务数据）

> 透明传输：

- **异步传输**：**字节填充**，转义字符`0x7D`
- **同步传输**：**零比特填充**

> 重要区别以太网：PPP 是点对点链路，**没有 CSMA/CD，无最短帧限制**，信息段可以 0 字节；以太网数据部分 46‑1500 字节。 PPP**面向字节**：帧长度一定是整数个字节。

###### 4、PPP 完整状态流转（拨号接入 ISP 流程）

1. **链路静止**：无物理层连接。
2. **物理层连接建立** → 进入**链路建立状态**：交互 **LCP 分组**，协商链路参数。
    - LCP 协商失败 → 返回链路静止。
    - LCP 协商成功 → 进入鉴别状态（PAP/CHAP 认证）。
3. 鉴别状态
    - 鉴别失败：链路终止。
    - 鉴别成功 → **网络层协议状态**。
4. 网络层协议状态：交互 **NCP(IPCP)**，ISP 分配临时 IP 地址。NCP 完成 → **链路打开状态**，可以传输 IP 报文。
5. 链路打开：正常收发用户 IP 数据。
6. 通信结束：LCP 释放链路，回到链路静止。

###### 5、PPP 四大特点（高频选择题）

1. PPP 只做 CRC 差错检测，**没有序号、没有确认重传机制，数据链路层是不可靠服务**。只检错，不纠错。
2. 仅支持**全双工点对点链路**，不支持多点线路。
3. 两端可运行不同网络层协议，共用同一条 PPP 链路。
4. 面向字节，帧长整数字节。

## 考试易错总结

1. LCP 管**链路层面**（还没 IP）；NCP 管**网络层参数 IP 地址**。
2. LCP/NCP 本身也是封装在 PPP 帧的「信息部分」，靠**协议字段区分类型**。
3. PPP 无 MAC 地址概念；A 地址字段 0xFF 是占位，不用于寻址。
4. PPP 信息字段可以 0 字节，以太网不可以。
5. PPP 数据链路层**不可靠**；只保证无差错接收（CRC 检测），不保证可靠交付，没有 ACK 确认。
