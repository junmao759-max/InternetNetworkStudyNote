                                    1. **可靠传输**：发送的数据全部准确交付接收方。依靠**确认 (ACK)+ 超时重传**实现。
1. **确认 ACK**：接收方收到正确帧，告知发送方。
2. **超时重传**：发送帧启动计时器，超时未收到 ACK，则自动重传该帧。
3. **ARQ（自动重传请求）**：依靠确认 + 超时重传实现可靠传输，分为三类：**停止等待、后退 N 帧 GBN、选择重传 SR**。

### 1. 停止 - 等待协议（SW）

1. 窗口大小 \(W_T=1，W_R=1\)；序号只用 1 比特：`0 / 1`交替编号。
2. 两类差错场景
    
    ① 数据帧出错 / 丢失：接收方无响应；发送方超时重传。
    
    ② ACK 确认帧丢失：接收方收到重复数据帧，直接丢弃，重新发送 ACK。
3. 特点：实现最简单；信道利用率极低。

### 2. 后退 N 帧协议（GBN，连续 ARQ）

1. 原理：发送方可以连续发送窗口内多帧，无需等待每一帧的 ACK。
2. **累积确认**：ACK n 代表：**0~n 号帧全部正确收到，期望接收 n+1 号帧**。
3. 核心缺陷：**接收方只能按序接收帧**。
    
    一旦某一帧出错 / 丢失，**该帧以及之后所有已经发送的帧全部需要重传**。
4. 适用场景：信道误码率较低的环境；信道差错多时，大量不必要重传，效率暴跌。

### 3. 选择重传协议（SR）

1. 优化目标：**只重传出错 / 丢失的帧，不重传后续正确到达的帧**。
2. 接收方能力：
    
    可以缓存**失序、但是序号落在接收窗口内**的正确帧；等到缺失帧修复后，一次性按序上交上层。
3. 机制：检测到帧出错，接收方发送否定确认 NAK，要求发送方单独重传指定帧。
4. 约束条件：\(\boldsymbol{W_T \le 2^{n-1}}\)，防止序号重叠无法区分新旧帧。
5. 优点：信道利用率最高；缺点：接收方需要缓存乱序帧，实现复杂。

## 4. 信道利用率计算

定义：发送周期内，**有效发送数据的时长 / 整个发送周期总时长**

符号约定：

\(T_D\)：单个帧发送时延；\(\text{RTT}\)：往返传播时延；\(T_A\)：确认帧发送时延（一般忽略）

### （1）停止 - 等待协议

\(U=\frac{T_D}{T_D+\text{RTT}+T_A}\)

### （2）连续 ARQ（GBN/SR，发送窗口大小n）

1. 情况 1：\(nT_D < T_D+\text{RTT}+T_A\)
    
    周期内发不完 n 个帧：

\(U=\frac{nT_D}{T_D+\text{RTT}+T_A}\)

2. 情况 2：\(nT_D \ge T_D+\text{RTT}+T_A\)

窗口足够大，信道持续填满，**信道利用率 \(U=1\)**

> 补充公式关系：
> 
> 信道平均传输速率 = 信道利用率 × 信道带宽

## 📌 考研高频易混总结

1. **GBN 接收窗口 = 1，只能顺序收；SR 接收窗口 > 1，可以缓存乱序帧**
2. GBN：出错**重传全部后续帧**；SR：**只重传出错的那一帧**
3. 序号位数n：
    
    - GBN 最大发送窗口：\(2^n-1\)
    - SR 最大窗口上限：\(2^{n-1}\)
    
4. 流量控制 ≠ 可靠传输：流量控制控制速率；可靠传输依靠重传机制保证数据不错不漏。
5. 链路层滑动窗口窗口固定；TCP 传输层滑动窗口接收方可以动态调整大小。
